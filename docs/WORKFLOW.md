# 工作流

> 本文讲「一个买入念头怎么一步步变成决定」；规则内容见 playbook，系统机制见 `DESIGN.md`。

## 1. 一只股票的流程

```
想法 ──→ 审查 ──→ 计划 ──→ 盯盘 ──→ 执行 ──→ 记录
```

| 阶段 | 回答 | 用到的规则 | 结果 |
| --- | --- | --- | --- |
| 想法 | 为什么想买？消息从哪来？ | I（必填理由） | 一句话理由 + 来源 |
| 审查 | 这只股票现在值得考虑吗？ | 上下文 V | 通过 / 否决（原因）/ 待回答 |
| 计划 | 怎么买？ | 候选 V（止损、悬空、阻力、盈亏比）；S 给出建议买点 | entry / stop / target / 过期日 |
| 盯盘 | 机会来了吗？还安全吗？ | 每个盘后：S 作触发器，复跑机器项 | 可执行 / 暂停（原因）/ 过期 |
| 执行 | 明天开盘怎么做？ | A（提醒） | 提醒；下单由人完成 |
| 记录 | 当时为什么这样决定？ | — | 日志一行（不买也记） |

- **审查一次性做完**；盯盘期间只复跑机器算的项。人的回答按有效期决定是否重新问。
- **同一组规则，不同阶段只是编排不同**：S 在「计划」里是推荐，在「盯盘」里是触发器。
- **暂停由机器判断，作废由人决定**：任一判定规则否决或未知 → 计划显示「暂停」并列出原因；解除后自动恢复。
- **计划会过期**：过期后续期或作废由人决定；人也可以随时作废。

## 2. 答案从哪来

| 来源 | 交互 |
| --- | --- |
| 机器算（行情、基本面） | 直接给结论 |
| 人画，机器判（区间、趋势线、颈线、旗形） | 人在档案中画；缺失或过期 → 提问 |
| 人回答（板块、消息面、基本面清单、想法理由…） | 缺失或过期 → 提问 |

每个回答的有效期写在读取它的 rule 块里（`ttl`）；结构默认 20 个交易日后过期，需复核。

## 3. 档案：一只股票一个文件

`data/tickers/<TICKER>.yaml`。人写，机器只读；将来 agent 也编辑这份文件。`data/tickers/` 目录就是 watchlist。

```yaml
ticker: AMD

idea:                          # 必填；载入为回答 idea.reason / idea.source
  reason: 数据中心 GPU 订单超预期
  source: news                 # news | research | chart | impulse
  at: 2026-10-01

facts:                         # 人的回答：值（布尔或数字）+ 确认日
  v07.no_bad_news: {value: true, at: 2026-10-01}
  v09.tracked:     {value: true, at: 2026-09-15}

exchange: NMS                  # 以下与 DESIGN §8 相同
zones: [...]
lines: [...]
absent: [...]

plans:
  - id: p1
    entry: 520
    stop: 500
    target: 600                # 可省略 → 盈亏比规则提问
    at: 2026-10-01
    expires: 2026-10-29        # 省略 = at + 20 个交易日
    status: active             # active | cancelled；「暂停」「过期」由机器算，不存
```

- **计划 = Candidate + 过期日 + 状态**，与 setup 产出的候选走同一组候选规则。
- **采纳系统建议 = 把建议的 entry / stop / target 抄进 `plans`**。

## 4. 报告：档案视图

1. **结论**（一行）：先写想法理由 / 不买（原因）/ 待回答 N 项 / 审查通过，尚无计划 / 计划 p1 可执行 / 计划 p1 暂停（原因）/ 计划 p1 已过期。
2. **待回答**：规则 ID + 提问 + 要填写的 key。
3. **计划**：状态、价格、rr、命中的规则。
4. **系统建议买点**：S 产出的候选，供抄入 `plans`。
5. **提醒**。

## 5. 编排与记录

同一条管道，加上档案文件：

```bash
# 盯盘：对 watchlist 逐个运行，并记录
for f in data/tickers/*.yaml; do
  t=$(basename "$f" .yaml)
  tradesys fetch "$t" | tradesys run playbooks/technical.md \
    | tee >(jq -c 'del(.snapshot.bars)' >> "data/journal/$t.jsonl") \
    | tradesys report
done
```

- **日志**只追加、不修改，不买也记。只保存事后无法重新获取的数据：结论与规则结果、当次的档案内容（回答、结构、计划）、当天才有的数据（基本面、财报日、期权报价）。日线可从 yfinance 重新下载，不保存。
- 将来的 agent 做同样的事：读「待回答」，向人提问，把回答写进档案，再跑一遍。
